# 01. プロダクトビジョン Q&A

実施日: 2026-05-12
オーケストレータが質問役、ユーザー本人が回答。

---

## Q1: UTAVISTA を再設計してまで完成させたい「一番の動機・解きたい問題」はどれが一番近いですか？

**提示した選択肢**
1. 手作業のもどかしさを AI で解消
2. 一般人でも MV 品質に到達させたい
3. 自分・身近な作家のツール（商用は二次的）
4. AI 生成 IR の技術検証・OSS

**回答**: 3. 自分・身近な作家のツール

---

## Q2: 「何が達成されれば UTAVISTA は完成だ」と言えるような状態を、どのイメージで描いていますか？

**提示した選択肢**
1. 「思った動きを言葉で頼めば即動く」体験
2. 豊富な IR + 人間の調整で可能性が広がる
3. テンプレ資産が累積して表現力が拡張していく
4. 完成は明確に定義していない

**回答（補足あり）**: 2 に近い。ただし「たくさんテンプレートを用意する」のではなく **「どんなテンプレートでも作れる下地をつくる」** イメージ。作りたいイメージができたとき、それを実現できる **土台が整っている状態** がゴール。

→ 重要: テンプレ供給量より **表現基盤の網羅性／拡張性** が完成の判定軸。

---

## Q3: 「どんなテンプレートでも作れる下地」と言うときの「どんな」の範囲は、どこまでを想定していますか？

**提示した選択肢**
1. 2D文字アニメの枠内で表現自由度を高める
2. 上記 + 3Dカメラ・3D変形・高度なエフェクト
3. 上記 + インタラクティブな表現
4. スコープ固定せず、必要に応じて拡張

**回答（補足あり）**: 基本は 1。ただし **2に近い** とも言える。具体的に含めたい拡張:
- **シェーダーエフェクト**（ノイズ、変形、色変化など）
- **マルチレイヤー歌詞**: 現状は1セットのスケッチレイヤーに1つの歌詞が対応している。バックコーラスや裏パートの歌詞などに対応する **サブレイヤーの歌詞アニメーション** を追加できる機能を実現したい
- **音声解析連動の自動パラメータ調整**: 入力した音声データの解析結果を用いて自動的にパラメータ調整。例:
  - キックの周期に合わせて文字サイズ変化
  - 音量変化に応じてシェーダーグラフィックの明るさ変化
  - ボーカル帯域の音の高さに合わせて文字の色を調整

→ これらは現ゴール文書 (`00-goal-vision.md`) に **未記載** の新規要件。後で反映が必要。

## Q4: 「自分・身近な作家のツール」と言うときの、使う人の規模感はどれが一番近いですか？

**提示した選択肢**
1. 基本は自分一人
2. 自分 + 信頼できる作家 5-10人
3. 上記 + 拡散しても受け入れる
4. 将来的には広く一般ユーザーに

**回答**: 3. 上記 + 拡散しても受け入れる

→ 帰結:
- 配布性は **ある程度** 必要（インストール可能、再現性のあるビルド）
- 派手なオンボーディング・マーケティング機能は不要
- OSS（GPL-3.0 + CC-BY-4.0）は維持
- 第三者が触ることも視野に入れた最低限の UI/UX 品質は必要

## Q5: UTAVISTA で主に制作したい「動画のジャンル」はどれに一番近いですか？

**提示した選択肢**
1. ボカロ・邦楽 MV 型の「歌詞動画」
2. カラオケ「誂い動画」型
3. 両方を含む汎用歌詞アニメ
4. VTuber/配信向け字幕・歌詞表示

**回答**: 1. ボカロ・邦楽 MV 型の「歌詞動画」

→ 帰結:
- 縦書き対応は維持（邦楽 MV では使う）
- カラオケ的な「歌唱ガイド」用途は中心ではないが排除はしない
- VTuber/配信のリアルタイム用途は当面スコープ外

## サマリー（このテーマで明確になったこと）

1. **動機**: 自分と身近な作家（5-10人 + 拡散OK）のための歌詞動画制作ツール
2. **完成像**: 大量のテンプレを揃えることではなく、**任意のアニメ要望を実現できる表現基盤が整った状態**
3. **表現スコープ**: 基本は 2D 文字アニメ。ただし下記3拡張を含む:
   - シェーダーエフェクト（ノイズ・変形・色変化など）
   - マルチレイヤー歌詞（バックコーラス・裏パート）
   - 音声解析連動の自動パラメータ調整（キック→文字サイズ、音量→明るさ、音高→色 等）
4. **ジャンル**: ボカロ・邦楽 MV 型「歌詞動画」
5. **配布**: OSS 継続。商用化は二次的。第三者が触る最低限の品質は確保

## ゴール文書 (`00-goal-vision.md`) に反映すべき修正点

1. **§1 全体のゴール表現**: 「シナリオA = 一般ユーザーの差分指示中心」は **完成像とややズレ**。完成の本丸は「**任意のアニメ要望を実現可能にする表現基盤の網羅性**」。シナリオAは「基盤が整った後に実現される一形態」として位置づけ直す
2. **§1.3 理想レイヤー構成への追加**:
   - **Shader 系 Atom**（ノイズ・変形・色変化など、フラグメント／頂点シェーダ層）
   - **AudioFeature 系 Atom**（FFT, ビート, 音量, ピッチを `t→feature(t)` の純関数として参照可能化）
   - **Layer 系構造**（複数の独立した歌詞アニメスタックを重ねられるサブレイヤー）
3. **§1.4 データモデル**: `lyrics` を単一の `PhraseUnit[]` ではなく、複数レイヤーを束ねる `LyricLayer[]` 構造に拡張
4. **§3 ギャップに追加**: G14 シェーダー表現、G15 音声解析連動、G16 マルチレイヤー歌詞構造
5. **§5 Option 選択**: 上記拡張要件があると、再設計範囲はさらに広がる。Option γ の「コア温存」境界も再評価が必要（音声解析パイプラインは新規？ 既存 v0.5.1 のBeatDetectorを流用？）

## 残された曖昧さ・追加で確認したい点（次テーマ以降で扱う）

- **3拡張要件の Phase 優先度**: シェーダー／マルチレイヤー／音声解析連動を、Phase 1 にどこまで含めるか
- **音声解析連動の制御モデル**: AI が IR で「音声特徴量 →パラメータ」のマッピングを直接記述するのか、別 UI で人間がマッピングを書くのか、両方併用か
- **マルチレイヤー歌詞の同期モデル**: メインレイヤーとサブレイヤーは独立時刻軸か、同一プロジェクト時刻か
- **シェーダーの記述レベル**: 既製シェーダーのパラメータ調整止まりか、GLSL を AI が書く想定もあるか
- **「土台が整った」の判定基準**: 第三者が触っての評価で測るのか、ユーザー自身の体感か
- **拡散時のサポート方針**: バグ報告・PR を受けるか、フォーク前提でリリースだけするか
- **ターゲット OS**: Windows / macOS / Linux のどれを優先するか
