# 03. AI 連携の運用モデル Q&A（テンプレ作成スコープ中心）

実施日: 2026-05-12

本テーマは「テンプレ作成における AI 連携」に絞った。「プロジェクト全体の自動化」は将来テーマ（11 を予定）として別建てで扱う。

---

## Q1: UTAVISTA から AI を呼ぶときの「接続方式」は、どれをメインにしたいですか？

**選択肢**
1. UTAVISTA 内蔵クライアントから直接 API 呼び出し
2. 外部 CLI/サービス連携（Claude Code 等）
3. ユーザーが作ったエンドポイントを叩く（n8n 等）
4. 上記の使い分け

**回答（補足あり）**: 2. 外部 CLI/サービス連携。**ただし理想的には ClaudeCode のスキルなどを用いて Cowork で画面キャプチャしつつ自動開発する想定**。

→ 帰結（重要）:
- UTAVISTA 内に AI を組み込むのではなく、**UTAVISTA は「外部から自動操作可能なインターフェース」を提供する**側
- API キー・コスト・セキュリティは ClaudeCode 側で管理、UTAVISTA は不要
- UTAVISTA 側で必要: スキル定義、外部から触れる手段（MCP / CLI / HTTP）、画面キャプチャに耐える UI 構造
- 「Cowork で画面キャプチャ」は **MCP/CLI（プログラム的操作）+ computer-use（視覚的確認）の併用** を示唆

---

## Q2: ClaudeCode スキル + Cowork で「自動開発」させたいスコープはどれが近いですか？

**選択肢**
1. テンプレ作成のみ
2. テンプレ作成 + パラメータ調整
3. プロジェクト全体（音源・歌詞・テンプレ・出力）
4. タスクごとの使い分け

**回答**: 4. **タスクごとに使い分け。最初はテンプレ作成にフォーカス、最終的には全機能操作可能にして完全自動化対応するのが理想**。

→ 帰結:
- Phase 1: テンプレ作成スキル
- 漸進的に拡張: パラメータ調整、プロジェクト全体操作
- 最終: UTAVISTA を MCP サーバとして全機能を外部から操作可能にする
- 各機能を「外部からプログラム的に呼べる」設計を最初から織り込む

---

## Q3: テンプレ作成スコープに限定して、AI とのコラボレーションフローはどう進めたいですか？

**ユーザーが提示したフロー（明文化されたもの）**:
> アニメーションイメージを言語化、AI に入力、対話して明確化、AI でラフ実装してイメージ確認

**選択肢で「その先」を確認**
1. 確認OK → ライブラリ保存（1発採用型）
2. 部分修正ループ（1-2回追加対話）
3. 複数案比較・試行錯誤型
4. ケースで使い分け

**回答**: **必要に応じて追加指示（最初は思いつかなかったけど、ラフが見えたら思いついた詳細なアニメーションや追加エフェクトなど）、このブラッシュアップを納得いくまで繰り返す**。

→ 帰結（重要）:
- 「最初の指示は不完全」が前提。ラフが見えてから追加要素が出てくる
- 修正ループは **回数を限定せず、納得いくまで繰り返せる** 必要
- AI 側のセッションは長いコンテキストを保持して、過去の応答を踏まえた追加修正ができる必要
- UTAVISTA 側は「現状 IR + 新指示」を ClaudeCode に渡し、新 IR を受け取って展開・プレビュー、ユーザー承認 or 追加指示のループ

## Q4: ブラッシュアップを繰り返している間の「履歴・戻り」の仕様はどれが一番使いやすそうですか？

**選択肢**
1. 最新版のみ保持、口頭で巻き戻し依頼
2. 数手の Undo
3. **全試行履歴を保持、任意の過去版に戻れる・分岐できる**
4. お気に入りピン留め

**回答**: 3. 全試行履歴を保持、任意の過去版に戻れる・分岐できる。

→ 帰結:
- **テンプレ生成 IR の Git-like バージョン管理機構が必要**
- 各 IR ノードに `parent`／`生成時の自然言語指示`／`生成時刻` 等のメタデータ
- UI 上で履歴ツリー表示 + 各ノードのサムネイル／プレビュー
- ブランチング（ある時点から別方向の試行を派生）
- マージは想定不要（テンプレ生成では分岐統合は稀）
- 採用版だけ「ライブラリ保存」へ昇格

---

## Q5: 「ラフ実装」（プレビューで見れる状態まで）の生成スピードとして、どれが許容レベルですか？

**選択肢**
1. 数秒以内
2. 30秒〜1分程度
3. 数分以内、バックグラウンド進行
4. 長時間OK（1本単位、何十分も有り）

**回答**: 4. 長時間OK（1本単位、何十分も有り）。

→ 帰結:
- **高品質志向**。リアルタイム応答性は要らない
- ClaudeCode + Cowork で長時間の自動推論を回す前提
- UTAVISTA 側は **生成中の進捗表示・キャンセル・完了通知・並行タスク管理** が必要
- 生成中もユーザーは他の作業（タイミング調整、別テンプレ検討、別プロジェクト）を進める前提なので、**生成は完全にバックグラウンドで動く**

---

## サマリー（このテーマで明確になったこと）

1. **接続方式**: 外部 ClaudeCode（+ 将来は他の自動化エージェント）と連携。UTAVISTA は **スキル/MCP/CLI を提供する側**
2. **自動化スコープ**: 段階的拡張。Phase 1 テンプレ作成、最終 UTAVISTA 全機能 MCP 化
3. **テンプレ生成フロー**: 言語化 → 入力 → 対話 → ラフ実装 → イメージ確認 → 追加指示 → 納得までブラッシュアップ
4. **履歴管理**: Git-like 全試行保持 + ブランチング + 任意過去版復帰
5. **速さ**: 長時間OK、バックグラウンド進行が前提
