## A. フェーズ1で確定した「決定事項」

### A-1. プロダクトビジョン

- **動機**: 自分・身近な作家（5-10人 + 拡散OK）のための歌詞動画制作ツール
- **完成像**: 大量のテンプレを揃えるのではなく、**任意のアニメ要望を実現できる表現基盤が整った状態**
- **動画ジャンル**: ボカロ・邦楽 MV 型「歌詞動画」
- **配布**: OSS 継続。商用化は二次的。第三者が触れる最低限の品質は確保
- **表現スコープ**: 2D文字 + シェーダー + マルチレイヤー + 音声解析連動

### A-2. 制作フロー

- **起点**: 楽曲・音声から
- **歌詞データ**: 外部マルチモーダルAI（Gemini 等）で生成 → UTAVISTA 取り込み。**UTAVISTA から外部API呼び出しを発火できる連携UI** が必要
- **テンプレ適用**: 既存ライブラリから手動選択 + 手動構成が基本。テンプレ不足時のみ AI に依頼（差分 or 新規）
- **AI 生成テンプレ保存**: 名前付きでライブラリ保存、他プロジェクトで再利用
- **マルチレイヤー / 音声解析の介入位置**: 事後判断・並行作業可能

### A-3. AI連携の運用モデル（テンプレ作成スコープ）

- **接続方式**: 外部 ClaudeCode（+ 将来は他の自動化エージェント）と連携。UTAVISTA は **スキル/MCP/CLI を提供する側**
- **API キー・コスト**: ClaudeCode 側で管理、UTAVISTA は不要
- **自動化スコープ**: 段階的拡張。Phase 1 テンプレ作成、最終 UTAVISTA 全機能 MCP 化
- **テンプレ生成フロー**: 言語化 → AI 入力 → 対話で明確化 → ラフ実装 → イメージ確認 → 追加指示 → **納得までブラッシュアップ**
- **履歴管理**: Git-like 全試行保持 + ブランチング + 任意過去版復帰
- **生成スピード**: 長時間OK、バックグラウンド進行が前提

### A-4. トラックアーキテクチャ（最大のパラダイムシフト）

- **DAW的トラック構造** を新方式の中核データモデル/UIに採用
- **テンプレ:トラック = 1:1**
- **3階層モデル (Phrase→Word→Char)** は歌詞トラック内部の実装として温存
- **個別アクティベーションの自然解消**: フレーズマーカーをどのトラックに置くかでテンプレ切替
- **トラックタイプ**: 歌詞 / シェーダー / タイトル/クレジット / 背景動画/画像/単色
- **統一モデル**: 全トラックが「1テンプレ + 時間配置情報（マーカー/クリップ）」で表現される
- **z軸**: トラック並び順 = z軸（DAW標準）。背景は最下位固定。ソロ/ミュート可
- **画像アセット管理機能** が新規必要（読み込み・適用・PIXI スプライト化）

### A-5. 音声解析連動

- **解析実行**: UTAVISTA 内蔵、ファイル読み込み時に一括解析・キャッシュ
- **特徴量**: 標準セット（音量・低中高帯域・ビート・ピッチ） + ユーザー追加可（カスタム帯域）
- **マッピング**: ハイブリッド（単純 mapping は UI、複雑式は IR 直記述）
- **マッピング適用範囲**: テンプレ作者が `audioMappable: true` で明示宣言したパラメータのみ
- **保存先**: .uta プロジェクトファイルに同梱
- **タイムラインへのビート視覚化＋スナップ**:
  - ビート（オンセット位置）にマーカー位置をスナップできる
  - **適応的主拍解析**: 楽曲のテンポゆらぎに追従し、主拍を解析してスナップポイントを自動設定
  - **過密回避**: ブレイクビーツ等で細かいビートがある場合も、見やすい粒度に間引く
  - データ層: `AudioAnalysis.beats` に加えて `mainBeats`／`localBPM`（時系列）も保持
  - 既存 BeatDetector（v0.5.1）では不十分な可能性、高度なアルゴリズム（aubio/librosa 系等）検討要
