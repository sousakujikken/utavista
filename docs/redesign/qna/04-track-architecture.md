# 04. マルチレイヤー/トラックアーキテクチャ Q&A

実施日: 2026-05-12

本テーマで **DAW的トラック構造** という大きなパラダイムシフトが起きた。データモデル全体・UI全体に影響する重要な決定。

---

## Q1: サブレイヤー歌詞とメインレイヤー歌詞の「時間軸の関係」は？

**選択肢**: 1) 全レイヤー同一時刻共有 / 2) 各レイヤー独立 / 3) 同期 + 任意オフセット / 4) ケースバイケース

**回答**: 1. 全レイヤーが同一プロジェクト時刻を共有。

→ シンプルに `t→state` を全レイヤーが共有する。レイヤーごとのオフセットは不要。

---

## Q2: 1プロジェクトで使うレイヤー数の想定は？

**選択肢**: 1) 主に2層 / 2) 3-4層 / 3) N層任意 / 4) 使ってみないと

**回答（補足あり）**: 歌詞アニメは主にメイン+サブの2層想定。**ただし、歌詞ではなく音楽データを入力としてパラメータ制御するグラフィックレイヤーを前面と背面に設定する余地があると理想**。

→ 帰結:
- 歌詞レイヤー (メイン+サブ): 2
- 音楽データ駆動グラフィックレイヤー (前景+背景): 2
- 合計4種類のレイヤー型

---

## Q3: 「音楽データ駆動グラフィックレイヤー」に載せたい要素のイメージは？

**選択肢**: 1) 動的図形/シェーダーのみ / 2) + 静的画像/動画オーバーレイ / 3) + テキスト要素（タイトル等）/ 4) 全部含む自由構成

**回答（重要な発展あり）**:

> 当初はメインサブの2レイヤーに1の動的図形／シェーダーを想定していましたが、確かにタイトル／クレジットのレイヤーは分けた方が操作が便利な気がします。むしろ **DAW的なインターフェイス** にして各テンプレートのトラックに歌詞のマーカーを配置することでそのテンプレートに対応した歌詞アニメーションがそのタイミングで表示されるインターフェイスの方がいい気がしてきました。トラックのバリエーションとして **テンプレート、シェーダーグラフィック、タイトル／クレジット、背景画像／動画／単色背景** などを配置して管理するUIがいいと思います。

→ **パラダイムシフト**: 「歌詞ベースのレイヤー」ではなく「**DAW的トラックアーキテクチャ**」に転換。

---

## Q4: DAW的トラック構造と現状の3階層モデル（Phrase→Word→Char）の関係は？

**選択肢**: 1) DAW中核、階層は歌詞トラック内部 / 2) 階層上位、トラックは補助 / 3) 一旦コミット保留 / 4) DAW化やめてレイヤー拡張だけ

**回答（明確化）**:

> DAWトラックと表現したのは、各テンプレートおよびシェーダー、背景動画、タイトルなどが **1トラックに対応** するマルチレイヤー的構造をさしています。**テンプレート内に複数トラックを想定するのではない**です。
>
> この前提において、3階層モデルは現状通り **フレーズ単位で1セット** として扱います。つまり、歌詞トラックについては **どのテンプレートにフレーズマーカーを配置するかによってそのフレーズの文字表示に適用するテンプレートを切り替えるUI** となります。フレーズに含まれる単語、文字については **フレーズのテンプレートを継承**、タイミングのみマーカー伸縮操作で調整する想定です。

→ 帰結（最重要）:
- **テンプレ:トラック = 1:1**
- 3階層モデル (Phrase→Word→Char) は **歌詞トラック内部の実装** として温存
- 「個別アクティベーション」が **構造的に置換される**: 「フレーズマーカーを別トラックに置く」だけで、そのフレーズに別テンプレが当たる
- 単語/文字レベルの個別テンプレ切替は **スコープ外**（Phrase が最小切替単位）

---

## Q5: 歌詞以外のトラック（シェーダー/タイトル/背景）のコンテンツ配置仕様は？

**選択肢**: 1) 複数クリップ配置 / 2) 1トラック=1コンテンツ全区間+アクティブ区間 / 3) タイプごと使い分け / 4) 保留

**回答（詳細）**:

> シェーダーは基本 **1トラック1種類のグラフィックパターン** が対応し、パラメータによるビジュアル制御と **アクティブ区間の設定** のみを想定しています。複数種類重ねる場合は複数のシェーダートラックを配置することになります。タイトル／クレジットは中身としては **歌詞トラックと同じ** でよく、タイトルやクレジット用のテンプレートを適用している状態を想定し、タイトル画像などを用いる場合は **画像をスプライト化して PIXI で扱えばいい** 認識です。なので **画像アセットの管理機能（読み込み、適用など）は必要** です。

→ 帰結:
- **統一モデル**: 全トラックが「1テンプレ + 時間配置情報（マーカー/クリップ）」で表現される
- 歌詞トラック: 配置 = フレーズマーカー（歌詞データへの参照）
- シェーダートラック: 配置 = アクティブ区間マーカー（ON/OFFと時間範囲）
- タイトル/クレジットトラック: 内容構造は歌詞トラックと同じ、テンプレが「タイトル用」
- 背景トラック: 配置 = 画像/動画/色 + 表示時間
- **画像アセット管理機能** が新規必要（読み込み、適用、PIXIスプライト化）

---

## Q6: トラックの「前後関係（z軸）」と「表示制御」の仕様は？

**選択肢**: 1) 並び順=z軸、ソロ/ミュート可 / 2) zIndex 明示指定 / 3) タイプで固定 / 4) DAWグループ化付き

**回答**: **基本1、背景だけ固定**。

→ 帰結:
- DAW標準: トラック並び順 = z軸 (上が前面)、ソロ/ミュート可、ドラッグ並び替え可
- **背景トラックだけは z軸最下位に固定** (ユーザーが誤って前面に出すリスク排除)

## サマリー（このテーマで明確になったこと）

UTAVISTA は **DAW的トラックアーキテクチャ** で再設計する。主要な構造:

### データモデル（新規）

```
Project {
  audio
  duration
  tracks: Track[]      // DAW的並列トラック
}

Track {
  id, name
  type: 'lyrics' | 'shader' | 'title' | 'background' | ...
  templateId: TemplateRef  // このトラックで使うテンプレ（1:1対応）
  parameters: TrackParameters
  clips: Clip[]
  visible: boolean
  solo: boolean
  // 並び順 = z軸（背景タイプは最下位固定）
}

Clip {
  startMs, endMs
  content: ClipContent  // type別
  parameterOverrides?: Partial<Parameters>  // クリップ単位の上書き
}

ClipContent = 
  | LyricPhraseRef       // 歌詞トラック: フレーズへの参照
  | ShaderActiveRange    // シェーダー: アクティブ区間のみ
  | TitleContent         // タイトル: テキスト/画像 + 表示
  | BackgroundContent    // 背景: 画像/動画/色

LyricPhraseRef {
  phraseId
  // 内部の Word→Char タイミングは歌詞データから引き、Phrase 範囲内でマーカー伸縮可能
}
```

### UI モデル（新規）

- DAW スタイル中央下タイムライン: 複数トラックを並列表示
- 各トラック左に: トラック名／テンプレ／パラメータ／ソロ/ミュート/可視
- 各トラック上に: クリップを時間軸上に配置
- ドラッグで並び替え（背景は最下位固定）
- マーカー伸縮で歌詞 Word/Char タイミング調整（Phrase 範囲内）
- 画像アセット管理パネル（別ドロワー）

### 「個別アクティベーション」の解消

- 現状: 1テンプレ全体適用 + 一部フレーズだけ別パラメータ
- 新方式: フレーズマーカーをどのトラックに置くかで決まる
  - サビだけ別テンプレ → サビフレーズマーカーをトラック B に置く
  - 同じテンプレで一部だけ色を変えたい → クリップ単位 `parameterOverrides`
- §1.7 の「階層的継承」モデルから「DAW的トラック分離」モデルに進化
