# 02. 制作フロー全体像 Q&A

実施日: 2026-05-12

---

## Q1: あなたが1本の歌詞動画を作るとき、「出発点」はたいてい何ですか？

**選択肢**
1. 楽曲・音声が先にあり、それに合わせてアニメを設計
2. 歌詞テキスト + 大まかなビジュアルイメージが先
3. ベーステンプレートを先に選んでから始める
4. 決まったフローはない・毎回違う

**回答**: 1. 楽曲・音声が先。

---

## Q2: 楽曲を読み込んだあと、「歌詞データ（テキスト + タイミング）」の準備は、再設計後の理想としてどうやりたいですか？

**選択肢**
1. 外部ツールで作ってインポート（現状延長）
2. UTAVISTA 内で歌詞テキスト + タイミング取得まで完結
3. AI に対話的に頼んで歌詞とタイミングを生成
4. 手動中心 + 補助的に自動解析

**回答（補足あり）**: 基本は 1。**ただし、Gemini などのマルチモーダル AI に「歌音声 + 歌詞 + フォーマット」を提供して JSON を出力してもらうフローを、UTAVISTA 内のインターフェースから外部 API 利用で実現したい**。

→ 帰結:
- 歌詞 JSON 作成は外部マルチモーダル AI に依頼するが、その API 呼び出しと結果取り込みを **UTAVISTA から実行できる UI/コネクタ** が必要
- 既存 [src/renderer/llm/](../../src/renderer/llm) はテンプレ生成用の試作だったが、**並列に「歌詞生成用」の API クライアントが必要**

---

## Q3: 歌詞データが整ったあと、「テンプレートを適用してアニメを仕上げる」ステップの理想の進め方はどれに近いですか？

**選択肢**
1. 手動テンプレ選択→AI で部分拡張（差分指示）
2. AI に最初からベーステンプレを作らせる
3. 手動主体、AI は補助
4. テンプレを使わず Atom IR を直接組み上げる

**回答**: **基本は既存テンプレを選んで手動構成。イメージに近いテンプレがない場合は AI に指示して作成**。

→ 帰結（重要）:
- ゴール文書のシナリオA（差分指示中心）／シナリオB（新規生成）の区分は **ユーザーレベルではなく用途レベル**: 同じユーザーが両方を使い分ける
- 「既存テンプレで足りる時は手動・AI 不要」「足りない時だけ AI に新規生成依頼」という運用
- 既存テンプレライブラリの **充実度と検索性** が AI 利用頻度を直接左右する

---

## Q4: AI に頼んで作ったテンプレートは、その後どう扱いたいですか？

**選択肢**
1. 名前付きでライブラリに保存して他プロジェクトでも再利用
2. プロジェクト埋め込みのみ、都度生成で十分
3. 「生成元テンプレ + 差分指示」のレシピで保存
4. 派生関係（系譜）まで保存

**回答**: 1. 名前付きでライブラリに保存して他プロジェクトでも再利用。

→ 帰結:
- ゴール文書のユーザーライブラリ路線をそのまま採用
- 派生関係追跡や差分レシピ保存などのオーバーエンジニアリングは不要
- ライブラリには「シナリオA で派生したテンプレ」も「シナリオB で新規生成したテンプレ」も同じ保存先に格納

## Q5: 「マルチレイヤー歌詞」と「音声解析連動の自動パラメータ調整」は、制作フローのどこに位置づけるイメージですか？

**選択肢**
1. プロジェクト開始時に事前設計
2. メインレイヤー完成後に後付け
3. テンプレ自体がレイヤー / 音声連動を内蔵
4. ケースバイケース

**回答（補足あり）**:
- **マルチレイヤー対応**: 事後判断想定。**ただしメインレイヤー完成後とは限らず並行で調整** する想定
- **音声解析**: 事後処理。**結果（各時間における所定の帯域の音量など）を用いてテンプレートのパラメータ調整に適用** する位置付け

→ 帰結（重要）:
- レイヤーは独立に編集可能、UI 上で切り替えながら **並行作業** できる必要がある（メイン完成を待たない）
- 音声解析の出力は **「時刻 t における特徴量」** として時系列確定したデータ。テンプレ側はこれを **`audio.kick(t)`／`audio.volume(t)`／`audio.vocalPitch(t)`** のような **純関数として参照** できる必要がある
- 音声特徴量参照は IR の Atom（`AudioFeature` ドメイン）として独立して扱う

## サマリー（このテーマで明確になったこと）

1. **制作の起点**: 必ず楽曲・音声から
2. **歌詞データ**: 外部マルチモーダルAI（Gemini 等）で生成 → UTAVISTA 取り込み。**UTAVISTA から外部API呼び出しを発火できる連携UI** が必要
3. **テンプレ適用**: 既存ライブラリから手動選択 + 手動構成が基本。テンプレ不足時のみ AI に依頼（差分 or 新規）
4. **AI 生成テンプレの保存**: 名前付きでライブラリに保存、他プロジェクトで再利用
5. **マルチレイヤー / 音声解析**: 事後判断・並行作業可能。音声特徴量は **時系列確定データ → テンプレパラメータへ純関数的に注入**
